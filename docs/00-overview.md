# 00 系統概觀

## 1. 這個系統是什麼

**線上題庫與測驗系統**是一個給課程使用的網頁平台：老師建立題庫、組成考卷並發佈測驗；學生在線上限時作答，交卷後由系統自動批改，並能查詢成績、檢討錯題與整理錯題本。

系統負責：

- **身份與角色**：註冊、登入、修改密碼、管理員重設密碼，以 `student` / `teacher` / `admin` 三種角色控管權限。
- **課程與修課**：老師開課、分章節；學生加入課程後才能參加該課程的測驗。
- **題庫管理**：單選、多選、是非、簡答四種題型；題目可設難度、解析與標籤。
- **考卷與測驗**：手動或隨機抽題組卷、配分、設定限時與開放時段、限制作答次數。
- **作答與批改**：伺服器計時、作答暫存、交卷後自動批改客觀題，簡答題由老師評分。
- **成績與統計**：個人成績與解析、各題答對率、班級平均、章節弱點分析。
- **學習輔助**：題目收藏與錯題本。

系統**不負責**：

- 防作弊監考（視訊、鎖定螢幕、切換視窗偵測）。
- 與校方 SSO、學務系統整合（帳號為本系統自建）。
- AI 自動出題、OCR 掃描題目、付費與金流。
- 即時通訊與推播通知。

## 2. 系統邊界

```
  學生 / 老師 / 管理員
          │  HTTP(S)
          ▼
  前端頁面 (HTML / CSS / JavaScript)
          │  fetch  /api/v1/...   (JSON)
          ▼
  PHP 後端 (public/api/index.php → Controller → Service → Repository)
          │  PDO (Prepared Statement)
          ▼
  MySQL 資料庫 "quiz_system" (InnoDB, utf8mb4)
```

設計上的關鍵事實：

- **沒有外部系統整合**：只有「瀏覽器 ↔ PHP ↔ MySQL」一條路徑，所有規則都集中在後端。
- **時間以伺服器為準**：開始時間、倒數與逾時判斷都在伺服器端，前端倒數只是顯示用。
- **MySQL 是唯一真相來源**：型別、外鍵、唯一鍵、CHECK 是最後一道防線，詳見 [02](02-database.md)。

## 3. 名詞定義

| 名詞 | 程式／資料表名 | 定義 |
| --- | --- | --- |
| 使用者 | `users` | 登入系統的帳號，以 `email` 登入。每個帳號只有一個 `role`。 |
| 須先改密碼 | `users.must_change_password` | 管理員重設密碼或建立帳號後為 `1`；使用者改密碼前只能使用 `GET /me`、`PUT /me/password`、`POST /auth/logout`。 |
| 學生 | `student` | `users.role = 'student'`。可修課、參加測驗、看自己的成績。 |
| 老師 | `teacher` | `users.role = 'teacher'`。可開課，並管理**自己課程**的題庫與考試。 |
| 管理員 | `admin` | `users.role = 'admin'`。可管理所有課程與使用者帳號。 |
| 課程 | `courses` | 一門科目，隸屬於一位老師（`teacher_id`）。 |
| 修課 | `course_enrollments` | 學生與課程的多對多關係。**未修課的學生不能參加該課程的測驗**。 |
| 章節 | `chapters` | 課程下的單元，題目歸屬於章節，供統計弱點使用。 |
| 題目 | `questions` | 題庫中的一題，屬於一個章節。 |
| 題型 | `questions.type` | `single` 單選、`multiple` 多選、`truefalse` 是非、`short` 簡答。 |
| 選項 | `question_options` | 題目的選項與是否為正確答案（`is_correct`）。簡答題沒有選項。 |
| 難度 | `questions.difficulty` | `1` 易、`2` 中、`3` 難。 |
| 標籤 | `tags` | 跨章節的主題分類，如 `SQL`、`JOIN`，與題目為多對多。 |
| 軟刪除 | `is_active = 0` | 題目停用但不實際刪除，以保留歷史作答紀錄。 |
| 考卷／測驗 | `exams` | 一份由題目組成的測驗，含限時、開放時段、及格分數與作答次數上限。 |
| 配分 | `exam_questions.score` | 某題在某份考卷中的分數；同一題在不同考卷可不同。 |
| 考卷狀態 | `exams.status` | `draft` 草稿、`published` 已發佈、`closed` 已關閉。 |
| 作答 | `exam_attempts` | 學生對某份考卷的一次作答（一張「單據」）。 |
| 作答序號 | `attempt_no` | 該學生對該考卷的第幾次作答，從 1 起算。 |
| 作答狀態 | `exam_attempts.status` | `in_progress` 作答中、`submitted` 已交卷、`graded` 已批改完成。 |
| 作答明細 | `attempt_answers` | 一次作答中，每一題的回答與得分。 |
| 勾選選項 | `attempt_answer_options` | 客觀題中，學生在該題勾選了哪些選項。 |
| 截止時間 | `deadline_at` | 該次作答的實際截止：`min(started_at + duration_min, exams.end_time)`。 |
| 收藏 | `bookmarks` | 學生標記的題目，可附筆記。 |
| 錯題本 | （計算而得） | 由作答明細中 `is_correct = 0` 的題目彙整，不另存資料表。 |

## 4. 使用者類型與各自看到的資訊

角色**存於 `users.role`**，一個帳號只有一個角色。「課程擁有者」不是角色，而是由 `courses.teacher_id` 判定的關係。

| 角色 | 看到的資訊 | 可做的事 |
| --- | --- | --- |
| 學生 `student` | 自己的資料、所有開放課程、自己已修課程的測驗、自己的作答與成績、被允許公開的解析 | 加入／退選課程、參加測驗、查成績、收藏題目、看錯題本 |
| 老師 `teacher` | 自己的資料、**自己開設課程**的全部章節／題目／考卷／修課名單／成績／統計 | 開課、管理章節與題庫、組卷與發佈、人工評分、看統計 |
| 管理員 `admin` | 全部課程與全部資料 | 老師可做的一切（不限自己的課程）、管理使用者帳號與角色 |

取捨：

- 老師無法以同一帳號參加別人課程的測驗；若有需求請另開學生帳號。
- 老師只能管理自己的課程；若要跨老師協作，由管理員處理（多老師共同授課列為擴充，見 [01](01-features.md)）。

## 5. 設計原則

1. **DB 是真相來源，schema 是契約。** 外鍵、唯一鍵、CHECK 保證資料正確；應用層驗證只是讓錯誤訊息更友善，不能取代 constraint。
2. **伺服器為準。** 計時、次數限制、計分全部在伺服器判定；前端傳來的任何分數、時間與狀態一律不採信。
3. **歷史不可改寫。** 作答紀錄與已被使用的題目不刪除、不改內容；題目用軟刪除；`exam_questions.score` 與 `question_options` 不允許在已有作答後變動。
4. **答案不外洩。** 學生在作答期間拿不到 `is_correct` 與解析；回傳給學生與回傳給老師使用**不同的資料結構**。
5. **權限看角色加擁有權。** 路由先檢查 role，再檢查資源是否屬於該老師的課程，不在程式中散落 `if user_id == 1` 之類的判斷。
6. **先做能用的最小版本。** P0 = 登入、課程、題庫、組卷發佈、作答批改、成績查詢；其餘漸進（優先級見 [01](01-features.md)）。
